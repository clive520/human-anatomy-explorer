# AI 自動化搜尋與資料探勘方法論 (AI Search & Data Mining Methodology)

在開發「人體解剖互動網站」的過程中，為了尋找高品質的 3D 模型與對應的醫學解剖資料，我運用了系統化的自動搜尋與探勘流程。以下為該流程的詳細拆解，這套方法論也能應用於未來的其他開發任務中。

---

## 1. 需求解析與關鍵字策略 (Query Strategy)
在尋找資源前，必須先將使用者的自然語言需求（例如：「我需要肌肉系統」）轉化為精確的技術查詢條件。
*   **確立檔案格式**：專案使用 Three.js，因此優先鎖定支援度最好且自帶材質的 `.glb` 或 `.gltf` 格式。
*   **確立特徵需求**：模型不能是一體成型的死物件，必須由「獨立且具備專業命名」的 Mesh（網格）組成，才能綁定點擊事件。
*   **關鍵字組合**：使用如 `"human muscle anatomy glb downloadable"`, `"vascular circulatory system gltf site:github.com"` 等組合。

## 2. 目標資料源鎖定 (Targeted Sourcing)
不依賴單一搜尋引擎，而是針對不同平台的特性進行分層搜尋：
1.  **開源社群 (GitHub)**：尋找前人做過的類似專案（如 BodyExplorer）。開源專案通常會附帶乾淨的資料庫（如 JSON 映射檔），是首選目標。
2.  **專業文獻與組織 (NIH, Human Reference Atlas)**：當尋找特定系統（如血管、神經）時，直接導向專業醫學圖書館（如 humanatlas.io），以確保解剖學的精確度。
3.  **3D 模型平台 (Sketchfab, CGTrader)**：作為備案，尋找以 CC 授權釋出的免費開源模型。

## 3. 啟動瀏覽器代理 (Autonomous Browser Subagent)
當搜尋結果不只是單純的文字，而是需要「進入網頁點擊、檢視、下載」時，我會啟動內建的 **Browser Subagent（瀏覽器子代理）** 進行模擬操作：
*   **動態探索**：指派任務給子代理（例如：「前往 HumanAtlas 網站，尋找男性血管系統的 GLB 下載連結」）。
*   **視覺驗證**：在遇到 UI 顯示異常（如血管模型跑到頭頂上）時，指示子代理開啟開發者本機伺服器 (`http://localhost:3000`)，並利用截圖（Click Feedback）來分析 3D 渲染的實際畫面。
*   **參數微調**：子代理可以直接在瀏覽器的 Console 中輸入 JavaScript，動態調整模型 `position` 和 `scale` 的數值，並回報最完美的對齊參數。

## 4. 資產驗證與結構分析 (Asset Verification)
下載模型後，絕對不直接盲目掛載至正式環境，而是先透過腳本進行「解剖」：
*   **編寫檢測腳本**：使用 Node.js 讀取下載回來的 `.glb` 檔案（如專案中的 `check_glb.js`）。
*   **解析節點**：印出模型中所有的 Node 與 Mesh 名稱（例如發現了 467 個肌肉 Mesh，或發現血管模型有 `VH_M_` 前綴）。
*   這一步是確保稍後撰寫資料庫時，Key-Value 對應能夠 100% 精準的關鍵。

## 5. 智慧資料融合 (Data Integration & Fallback)
將下載下來的模型與我們自己的資料庫結合，並加上容錯機制：
*   **資料清洗**：爬取原始專案的 Mapping JSON，轉寫成專案需要的格式。
*   **建立智慧後備 (Fallback)**：預判資料庫可能會有遺漏。透過正則表達式（Regex）處理字串，將未收錄的 Mesh 英文名稱自動過濾底線、首字母大寫，並藉由關鍵字（如 `vein`, `artery`, `phalanx`）自動推斷所屬系統，確保使用者「點任何地方都不會出錯」。

---

### 💡 總結
這個工作流結合了 **「精準搜尋 → 代理人視覺操作 → 腳本驗證 → 邏輯融合」**。這不僅僅是「上網找檔案」，而是具備容錯與除錯能力的自動化開發閉環，確保外部資源能完美、穩定地融入我們正在開發的系統中。
